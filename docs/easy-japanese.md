# やさしい日本語の決まり（教材）

作者が「日本語が難しすぎる。もっとやさしく」と感じたため決めた。目安は「中学生でも読める」。教材（`content/`）と画面の文言の両方に使う。

## 文の書き方

- **です・ます**で書く。「〜である」「〜だ」は使わない
- **1文は短く**。目安は 40 字まで。1文に言いたいことは1つ。「〜し、〜して、〜なので」とつなげない
- **結論を先に**。「つまり何か」を最初に書き、理由はあとに書く
- **話しかけるように**。「〜しましょう」「〜と覚えておきましょう」もよい
- 漢字が続く言葉を、ふだんの言葉に言いかえる

| 難しい言葉 | やさしい言葉 |
|---|---|
| 計上する | 数に入れる、帳簿に書く |
| 調達する | 集める |
| 毀損する、損なう | 傷つける、なくす |
| 留意する | 気をつける |
| 抑制する | おさえる |
| 乖離、ずれ | 差、ずれ |
| 〜を勘案して | 〜も考えて |
| 〜に資する | 〜の役に立つ |
| 当該 | その |
| 顕在化する | 表に出てくる |

## 専門用語の扱い

- 経営者として覚えたい言葉（PL、営業利益、減価償却、RevPAR、NPV など）は**残す**。そのかわり、そのテーマで初めて出るところで、すぐ後ろに**やさしい説明**を付ける
  - 例：「減価償却（げんかしょうきゃく）とは、高い買い物を、使う年数に分けて少しずつ費用にすることです」
- 読み方が難しい言葉には、初めて出るところで（ ）に読みを書く。例：売掛金（うりかけきん）
- 英語の略語は、もとの意味を一言で。例：RevPAR（レブパー）＝ 販売できる1部屋が、空室も含めて平均いくら稼いだか
- **たとえ話**を使う。例：「PL は1年分の通知表、BS は決算日に撮った写真です」

## 変えてはいけないもの

- ID（`id`、`themeId`、問題の `id`、選択肢の `a`〜`d`）、`answer`、`field`、`order`、`connections` の `to`、`relatedThemes`
- 数字と計算。表の数字、問題の正解、ケースの `effects`（増減表）の数字は1つも変えない
- 法務・税務の中身。条文の番号、税率、期限、`sources`、`asOf`。やさしく言いかえても、意味（条件や例外）を落とさない。「必ず」「だけ」を足さない
- YAML の形。`,` や `:` を含む文は `"` で囲む

## 気をつけること

- 本文の `##` 見出しを変えたら、`quiz.yaml` の `reviewSection` も同じ文字に直す
- 見出しは、内容がひと目でわかる短い言葉にする（例：「5つの利益」→「利益は5段階ある」）
- 書き直したら、`apps/ceo-academy` で `npm test` を実行して、誤りがないことを確かめる
